# 多卷联映排练台

由「胶片分镜条核对台」扩展而来的纯前端本地应用：多个胶片卷共享同一个片段库，支持替代片段约束核对、
排练记录、多页面分叉合并与人工裁决、定版只读，以及完整的撤销重做、刷新与导入导出一致性。

直接打开 `index.html` 即可使用（也可以在本目录启动静态服务访问）。数据保存在浏览器 localStorage，
旧版单卷核对台数据首次打开时自动迁移（旧片段进入共享库并由一卷引用）。

## 功能

- **共享片段库**：片段只在库里存一份，多卷以"排片位置"引用；在库里修改片段（时长、颜色、破损、备注）
  会立即同步所有引用它的卷，并自动重算每卷总时长与风险分；卡片上标明该片段被哪些卷引用。
- **替代片段**：每个排片位置可安排替代。约束为 ① 颜色偏移一致 ② 破损程度不能更严重
  ③ 时长在 ±max(2 秒, 15%) 容差内。候选列表按合规度排序，**冲突逐条列出（颜色/破损/时长各自说明）**；
  不满足时确认按钮禁用，知悉冲突并勾选后才可强制安排，强制替代会一直保持阻断直到处理。
- **排练记录**：逐位记录实际顺序、实际放映来源（原片/替代）、延误秒数与延误原因、替换原因。
  "需跳过"原片必须安排合规替代；有延误必须写原因；使用替代必须写替换原因。
- **阻断与定版**：未处理阻断（未排练、替代冲突、需跳过无替代、引用缺失、缺原因等）存在时**不能定版**；
  定版后整卷只读，并冻结引用到的库片段快照——之后共享库再改也不影响已定版卷。可"退回草稿"重新编辑。
- **两个页面分叉按版本合并**：每个页面基于共同祖先（revision/baseState）工作。
  - 不重叠的修改在提交时或收到 storage 事件时**自动三路合并**；
  - 双方改同一字段为不同值、删除与修改冲突、删除共享片段导致引用悬空、双方排片/排练顺序调整不一致，
    都会弹出裁决框，**逐条展示冲突，必须人工选择（对方版本/本页版本/删除/保留），未全部裁决不能应用，
    绝不静默覆盖**；也可放弃本页修改整体采用对方版本。
  - 工具栏「暂停同步（分叉排练）」可让两个页面稳定地各自分叉，恢复同步时再自动合并或进入裁决。
- **一致性**：撤销/重做同样走进分叉合并（不会覆盖其他页面的更新）；刷新后状态、定版、排练记录一致；
  导入为整体替换（可撤销），导出为完整工程 JSON；另保留原核对台的颜色筛选、关键词搜索、颜色/破损提醒、
  本卷 TXT 清单导出。
- **异常导入**：JSON 解析失败或结构错误（坏时长、重复 id、悬空引用、坏枚举等）会逐条列出错误位置与原因，
  拒绝导入且不改动现有数据；非致命问题（未知枚举、失效替代引用等）作为警告自动修正后导入。

## 文件结构

| 文件 | 职责 |
| --- | --- |
| `model.js` | 领域纯函数：派生时长/风险、替代约束、阻断、提醒、定版冻结、旧数据迁移、导入校验 |
| `merge.js` | 实体级三路合并与冲突登记（字段 / 删除-修改 / 引用完整性 / 顺序冲突） |
| `store.js` | localStorage、revision 与共同祖先、提交碰撞检测、storage 事件、暂停同步、撤销重做、导入导出 |
| `app.js` / `index.html` / `styles.css` | 界面 |
| `test/` | Node 内置 test runner 的单元测试（model / merge / store，28 项） |
| `e2e/e2e.js` | Playwright 真实浏览器走查（59 项断言，覆盖共享修改、替代、分叉合并与裁决、定版、异常导入、原流程回归） |

## 运行测试

```bash
node --test test/          # 单元测试
node e2e/e2e.js            # 浏览器端到端（需 npx playwright install chromium）
```
